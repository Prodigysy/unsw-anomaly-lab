Студент №16 → `variant = ((16 − 1) % 5) + 1 = 1` → **метод `zscore`**.

## 1. Что за задача

Дан учебный набор на основе UNSW-NB15: записи сетевых соединений (47 колонок — метаданные
потока: длительность, пакеты, байты, TTL, TCP-тайминги, счётчики соединений и т.д.).
Два файла: train (175 341 строка) и test (82 332). Колонка `label` — истина (1 = атака).

Суть: метод **без учителя** должен присвоить каждой строке число `anomaly_score`
(чем больше — тем «аномальнее») и флаг `is_anomaly` по порогу. Метки используются
**только** для оценки качества в `evaluate` — ни на обучение, ни на выбор признаков,
ни на подбор порога они не влияют.

## 2. Идея метода z-score

Для каждого признака $j$ считаем на train среднее $\mu_j$ и std $\sigma_j$ (ddof=0):

$$z_{ij} = \frac{x_{ij} - \mu_j}{\sigma_j}$$

Score строки — агрегация `max_abs_z`: $\text{score}_i = \max_j |z_{ij}|$.
Строка аномальна, если хотя бы один признак «улетел» дальше $k$ сигм. Порог —
классическое правило трёх сигм, $k = 3.0$ из `config/config.yaml`.

Почему агрегация `max`: аномалия в трафике обычно проявляется в *одном* измерении
(гигантский `sbytes`, нулевой `dur`, аномальный `rate`). Максимум по признакам
ловит «любой выброс», а не требует экстремальности сразу везде.

## 3. Пайплайн препроцессинга (и почему так)

Порядок: **missing → transform → стандартизация → score**.

| Параметр | Значение | Обоснование |
|---|---|---|
| `missing: median` | заполнение медианой по train | В числовых признаках NaN нет (EDA, график 02) — политика страховочная; медиана устойчивее нуля к тяжёлым хвостам |
| `transform: none` | без log-преобразования | Хвосты тяжёлые (skew до 167), но signed_log1p сжимает дискретные счётчики `ct_*` (0/1/2 почти неразличимы после log1p) и не помогает ранжированию |
| `scaling: none` | без отдельного скалера | z-score сам и есть стандартизация; второй скалер был бы дублем |
| `fit_on: train` | только `split == "train"` | Требование задания; в стартовом конфиге стояло `all` — утечка |
| `zero_variance: epsilon` | std=0 → 1e-12 | Защита от деления на ноль; на train нулевой дисперсии нет |

Все $\mu_j, \sigma_j$, медианы и порог хранятся в модели (`model.joblib`) и применяются
к test без пересчёта — это и есть отсутствие утечки.

## 5. Что показал EDA

- **Баланс**: атак 68% (train) и 55% (test) — «атака» здесь класс-большинство.
- **Пропуски**: только `payload_preview` (недоверенный текст, исключён); в признаках NaN нет.
- **Распределения**: почти все объёмные признаки — мода в нуле + единичные гигантские
  значения (skew 40–167). Медиана max|z| по train ≈ 1.97: «типичная» строка уже на ~2 сигмах.
- **Корреляции**: выраженные блоки (пакеты/байты/потери; TCP-тайминги; счётчики `ct_*`).
- **Почти константных/нулеводисперсных** признаков на train нет → список признаков (39)
  не сужался.

Следствие: порог k=3 флагует **26.5%** тестовых строк — правило сигм на этих данных
заведомо «шумит», потому что распределение max|z| далеко от нормального (график 05).

## 6. Результаты (реальный запуск CLI)

| Метрика | Значение |
|---|---|
| precision | 0.4884 |
| recall | 0.2346 |
| F1 | 0.3169 |
| ROC-AUC | 0.3778 |
| Confusion matrix | TN=25861, FP=11139, FN=34698, TP=10634 |
| Доля флагов | 26.45% (21773 из 82332) |

**Главный вывод: ROC-AUC < 0.5.** Это не ошибка пайплайна, а содержательный результат:
атаки в UNSW-NB15 — не статистические выбросы, а *плотные кластеры* (массовые DoS,
сканирования повторяют одни и те же значения), поэтому «удалённость от среднего»
антикоррелирует с атакой. Глобальное правило сигм принципиально плохо ранжирует такие
данные — нужны локальные методы (KNN-расстояние, LOF) или One-Class SVM (варианты 3–5).

## 7. Как устроен CLI (`scripts/anomaly_cli.py`)

Одна реализация метода, которую переиспользует и ноутбук (импорт функций):

- `stats` — строки train, пропуски, нулевая дисперсия, min/max/mean/std; сохраняет `stats.json`.
- `train` — медианы + mean/std только по train; сохраняет `model.joblib` (словарь с полями
  `method, features, params, preprocessor, estimator, state, threshold`) и `model_meta.json`.
- `detect` — применяет модель к CSV; фильтр `split == test` (отключается `--split all`);
  добавляет `anomaly_score`, `is_anomaly`; исходные колонки не трогает.
- `evaluate` — P/R/F1/ROC-AUC (ранговая формула Манна–Уитни) + CM; пишет `metrics.json`
  и `confusion_matrix.md`.

Коды возврата: 0 — успех, 2 — ошибка конфигурации/аргументов, 3 — ошибка данных;
ошибки печатаются одной строкой без traceback.

## 8. Как воспроизвести

```bash
pip install -r requirements.txt
python scripts/anomaly_cli.py stats    --config config/config.yaml --output artifacts/reports/stats.json
python scripts/anomaly_cli.py train    --config config/config.yaml --model-dir artifacts/models
python scripts/anomaly_cli.py detect   --config config/config.yaml --model-dir artifacts/models \
    --input data/UNSW_NB15_testing-set.csv --output artifacts/predictions.csv
python scripts/anomaly_cli.py evaluate --config config/config.yaml \
    --predictions artifacts/predictions.csv --ground-truth label
```

Ноутбук `notebooks/anomaly_detection_fixed.ipynb` выполняется целиком (Jupyter / VS Code);
последняя ячейка перегенерирует артефакты той же реализацией, что и CLI, — результаты
гарантированно совпадают.
