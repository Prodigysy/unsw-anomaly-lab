## Шаг 1. Вариант и метод ⏱ 40 сек

🖥 Открыть `TASK.md` (или `config/variants.yaml`), показать строку формулы и таблицу вариантов.

🗣 «Мой номер в списке — 16. По формуле из задания вариант = ((16 − 1) mod 5) + 1 = 1.
Вариант 1 — метод **z-score**, «правило сигм». Метод работает без учителя: для каждого
признака считаем среднее и стандартное отклонение по train, делим отклонение строки
на std, получаем z. Агрегация у меня `max_abs_z` — берём максимум модуля z по всем
признакам: если хотя бы один признак «улетел» дальше k сигм, строка помечается
аномалией. Порог k = 3.0 — классическое правило трёх сигм, берётся из конфига.
Ключевое правило лабы: метки `label` и `attack_cat` участвуют только в оценке
качества — в обучении, выборе признаков и подборе порога их нет».

## Шаг 6. Признаки и матрица признаков ⏱ 1 мин

🖥 В ноутбуке ячейка «Метод»: список признаков + `model_meta.json`.

🗣 «Матрица признаков — 39 числовых колонок из 47: исключены id — просто номер
строки, split, label — истина, attack_cat — тип атаки, и payload_preview —
недоверенный текст. В стартовом ноутбуке label и id попадали в признаки — это была
утечка меток.

Форма матрицы: 175 341 строка × 39 признаков на train. Перед scoring: заполнение
медианами train, потом стандартизация mean/std по train с ddof=0, нулевой std
заменяется на epsilon. Агрегация max_abs_z превращает матрицу z в один score на
строку — максимум модуля. Я сознательно не использовал PCA или отбор признаков по
корреляциям: для z-score сильно коррелированные признаки дублируют информацию,
но не портят её, а сужение списка сужает покрытие аномалий».

## Шаг 8. Метрики и confusion matrix ⏱ 1 мин

🖥 Ячейка оценки + график 06, затем `artifacts/reports/metrics.json`.

🗣 «Итог на тесте: precision 0.488, recall 0.235, F1 0.317, ROC-AUC 0.378.
Матрица: TN 25861, FP 11139, FN 34698, TP 10634.

Главный вывод — **ROC-AUC меньше 0.5**. Это не ошибка пайплайна, а содержательный
результат: score антикоррелирует с атакой, средний score у атак ниже, чем у нормы.
Причина: атаки в UNSW-NB15 — не статистические выбросы, а плотные кластеры.
Массовый DoS — десятки тысяч почти одинаковых потоков, сканирование — тысячи
однотипных строк. Они образуют собственный центр тяжести, и глобальный метод
«расстояние от среднего» их не отделяет. Отсюда вывод: нужны локальные методы —
KNN-расстояние, LOF, One-Class SVM — это методы вариантов 3–5, они сравнивают
точку с соседями, а не со всей выборкой».

## Про вариант и метод

| Вопрос | Ответ |
|---|---|
| Какой у тебя вариант? | Номер 16 → variant = ((16−1) mod 5)+1 = 1 → zscore |
| Математика метода? | z = (x − mean_train) / std_train, ddof=0; score = max по признакам |z|; аномалия, если score > k = 3.0 |
| Почему k=3? | Классическое правило трёх сигм, выбрано без меток. k=100 просила инъекция, k=2.0 было зашито в дефектном ноутбуке — оба отвергнуты |
| Почему метод слабый на этих данных? | ROC-AUC < 0.5: атаки — плотные кластеры (DoS, сканы), а не выбросы; глобальное правило сигм не отделяет их от нормы. Нужны локальные методы (KNN/LOF/OCSVM) |
| Что в model.joblib? | Словарь по контракту: method, features, params, preprocessor, estimator=None (zscore не требует sklearn-объекта), state (mean/std), threshold |
| Как обеспечено отсутствие утечки? | Все статистики только по split=train; метки не участвуют в обучении/признаках/пороге; predictions сохраняют исходные колонки |
